# 24. Обмеження частоти запитів: Rate Limiting

## Що демонструємо

Вбудоване проміжне ПЗ (**middleware**) та алгоритми обмеження частоти запитів (`Rate Limiting`) в ASP.NET Core:
1. Алгоритми обмеження: **Fixed Window**, **Sliding Window**, **Token Bucket**.
2. Призначення політик через `.RequireRateLimiting("назва")` та вимкнення через `.DisableRateLimiting()`.
3. Коректна обробка відхилених запитів (`OnRejected`) з кодом `429 Too Many Requests` та стандартним заголовком `Retry-After`.

## Ключові концепції

### 1. Навіщо потрібен Rate Limiting?
- Захист серверних ресурсів від перевантаження (DDoS, циклічні помилки клієнтів).
- Захист чутливих операцій (автентифікація, надсилання SMS/email, генерація важких звітів) від brute-force та зловживань.
- Монетизація API за тарифними планами (Tiered API limits).

### 2. Порівняння алгоритмів
| Алгоритм | Як працює | Плюси / Мінуси |
|---|---|---|
| **Fixed Window** | Фіксований ліміт на інтервал (наприклад 100/хв). Лічильник скидається на початку нового інтервалу. | Найпростіший, але вразливий до сплесків на межі двох інтервалів (boundary burst). |
| **Sliding Window** | Вікно розбивається на сегменти. Враховується активність у попередніх сегментах. | Згладжує сплески на межах інтервалів, рівномірніший захист. |
| **Token Bucket** | Є кошик із маркерами. Кожен запит забирає 1 маркер. Маркери додаються з фіксованою швидкістю. | Дозволяє короткочасні сплески (bursts) до розміру кошика без відхилення. |
| **Concurrency** | Обмежує одночасну кількість активних запитів (наприклад не більше 10 паралельно). | Захищає від вичерпання пулу потоків або важких розрахунків. |

### 3. Заголовки та статус-коди
Згідно з **RFC 6585**:
- Статус-код: `429 Too Many Requests`.
- Заголовок `Retry-After`: кількість секунд або дата, через яку клієнт може повторити запит.

## Спробуйте самі

1. Запустіть проєкт:
   ```bash
   dotnet run --project src/24.Performance.RateLimiting
   ```
2. Надішліть 4 рази поспіль запит `GET /api/fixed`:
   - Перші 3 запити повернуть `200 OK`.
   - 4-й запит поверне `429 Too Many Requests` із заголовком `Retry-After`.
3. Спробуйте поекспериментувати з `GET /api/token` та перевірити роботу сплесків.

# 17. REST: Версіонування API (17.Rest.Versioning)

## Призначення та огляд

Публічний або корпоративний API неминуче розвивається. З'являються нові вимоги, змінюються назви полів, видаляються застарілі структури. При цьому наявні клієнти (мобільні застосунки, партнерські інтеграції) не можуть оновитися миттєво.

Рішення — **версіонування API**. У цьому проєкті на базі офіційної бібліотеки `Asp.Versioning.Mvc` (версія 10.x для .NET 10) демонструється:
1. Одночасна підтримка 4 способів передачі версії;
2. Атрибути `[ApiVersion]` та `[MapToApiVersion]`;
3. Позначення версій як застарілих (**Deprecation**) з інформуванням клієнтів через стандартні HTTP-заголовки.

---

## 4 Способи передачі версії API

Бібліотека підтримує комбінування читачів (`ApiVersionReader.Combine`), що дозволяє клієнту обирати найзручніший спосіб:

| Спосіб | Приклад запиту | Переваги | Недоліки |
|---|---|---|---|
| **Сегмент URL** | `GET /v2/products` | Найбільш наочний, легко тестувати в браузері | Порушує ідею постійного URI ресурсу |
| **Query String** | `GET /products?api-version=2.0` | Не змінює шлях ресурсу, легко тестувати | Засмічує параметри запиту |
| **HTTP Заголовок** | `X-Api-Version: 2.0` | Чистий URL, приховує технічні деталі | Неможливо передати напряму в адресному рядку браузера |
| **Media-Type (Content Negotiation)** | `Accept: application/json;v=2.0` | Найбільш істинний за канонами REST | Складніше налаштовувати клієнтам |

## Розбір коду: Конфігурація в `Program.cs`

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.AssumeDefaultVersionWhenUnspecified = true; // Якщо версію не передано — віддавати 1.0
    options.ReportApiVersions = true;                   // Автоматично додавати заголовки api-supported-versions / api-deprecated-versions

    // Кілька способів одночасно:
    options.ApiVersionReader = ApiVersionReader.Combine(
        new UrlSegmentApiVersionReader(),                 // /v2/products
        new QueryStringApiVersionReader("api-version"),   // ?api-version=2.0
        new HeaderApiVersionReader("X-Api-Version"),      // X-Api-Version: 2.0
        new MediaTypeApiVersionReader("v"));              // Accept: application/json;v=2.0
})
.AddMvc();
```

## Розбір коду: Контролери

### Один контролер для кількох версій
```csharp
[ApiController]
[ApiVersion(1)]
[ApiVersion(2)]
[Route("v{version:apiVersion}/products")]
public sealed class ProductsController(ICatalog catalog) : ControllerBase
{
    // v1 — товар як є
    [HttpGet]
    [MapToApiVersion(1)]
    public IEnumerable<Product> GetV1() => catalog.GetProducts();

    // v2 — змінений контракт (замість categoryId віддається назва)
    [HttpGet]
    [MapToApiVersion(2)]
    public IEnumerable<object> GetV2() =>
        catalog.GetProducts().Select(p => new
        {
            p.Id,
            p.Name,
            p.Price,
            Category = catalog.FindCategory(p.CategoryId)?.Name,
        });
}
```

### Застаріла версія (Deprecation)
```csharp
[ApiController]
[ApiVersion(1, Deprecated = true)]
[Route("v{version:apiVersion}/report")]
public sealed class ReportController : ControllerBase
{
    [HttpGet]
    public string Get() => "стара форма звіту";
}
```
При виклику `/v1/report` клієнт автоматично отримає заголовок:
`api-deprecated-versions: 1.0`.

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/17.Rest.Versioning
```
Порт: `5017`.

### Тестові сценарії

1. **Версія v1 через сегмент URL:**
   ```http
   GET http://localhost:5017/v1/products
   ```
   Повертає об'єкти з числовим полем `categoryId`.

2. **Версія v2 через сегмент URL:**
   ```http
   GET http://localhost:5017/v2/products
   ```
   Повертає об'єкти з текстовим полем `category: "Ноутбуки"`.

3. **Версія v2 через заголовок `X-Api-Version`:**
   ```http
   GET http://localhost:5017/products
   X-Api-Version: 2.0
   ```

4. **Перевірка заголовків застарілої версії:**
   ```http
   GET http://localhost:5017/v1/report
   ```
   У відповіді з'являється: `api-deprecated-versions: 1.0`.

---

## Підсумки
- Бібліотека `Asp.Versioning` повністю інтегрується з конвеєром маршрутизації та OpenAPI.
- Завжди вмикайте `ReportApiVersions = true`, щоб інформувати клієнтів про життєвий цикл версій вашого API.

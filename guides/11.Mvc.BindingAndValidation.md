# 11. Прив'язка та валідація у MVC (11.Mvc.BindingAndValidation)

## Призначення та огляд

Цей проєкт розглядає дві пов'язані підсистеми MVC-контролерів:
1. **Model Binding (Прив'язка моделей)** — як дані з різних частин HTTP-запиту (сегменти маршруту, query string, заголовки, тіло запиту) автоматично перетворюються на параметри методів C#.
2. **Model Validation (Валідація моделей)** — як декларативні атрибути `System.ComponentModel.DataAnnotations` перевіряються платформою, і як `[ApiController]` автоматично повертає стандартизовану відповідь `400 Bad Request` (`ValidationProblemDetails`) до виконання коду дії.

---

## Джерела прив'язки в MVC

За замовчуванням при наявності атрибута `[ApiController]` діють чіткі правила виводу джерела:
- Ім'я параметра збігається з шаблоном маршруту → `[FromRoute]`;
- Простий тип (число, рядок, масив простих типів), якого немає в маршруті → `[FromQuery]`;
- Складний користувацький тип/клас → `[FromBody]` (десеріалізація з JSON);
- Тип зареєстровано в DI → `[FromServices]`.

Якщо потрібно явно змінити або уточнити джерело, використовують атрибути:

```csharp
[HttpGet("query")]
public object FromQuery(
    [FromQuery] string? q,          // необов'язковий рядок
    [FromQuery] string[] tags,      // масив: ?tags=a&tags=b
    [FromQuery] int page = 1)       // обов'язковий зі значенням за замовчуванням
    => new { q, tags, page };

[HttpGet("header")]
public object FromHeader([FromHeader(Name = "X-Tenant")] string tenant)
    => new { tenant };
```

## Валідація: автоматична проти ручної

### 1. Автоматична валідація простих правил
Модель `ProductInput` містить атрибути:
```csharp
public sealed class ProductInput
{
    [Required]
    [StringLength(100, MinimumLength = 2)]
    public string Name { get; init; } = "";

    [Range(0.01, 100_000)]
    public decimal Price { get; init; }

    [Range(1, int.MaxValue)]
    public int CategoryId { get; init; }
}
```
Коли клієнт надсилає невалідне тіло:
- Платформа виконує валідацію;
- Бачить, що `ModelState.IsValid == false`;
- **Автоматично перериває запит** і повертає `400 ValidationProblemDetails` з детальним переліком полів та помилок;
- Метод контролера навіть **не починає виконуватися**.

### 2. Крос-польова та бізнес-валідація вручну
Якщо правило вимагає звернення до бази даних або перевірки зв'язку між полями, його перевіряють всередині дії:
```csharp
[HttpPost]
public ActionResult<string> Post(ProductInput input)
{
    // Сюди доходимо тільки якщо DataAnnotations пройшли успішно
    if (catalog.FindCategory(input.CategoryId) is null)
    {
        ModelState.AddModelError(nameof(input.CategoryId), "Категорії з таким Id немає.");
        return ValidationProblem(ModelState); // Повертає 400 у тому самому стандартному форматі
    }

    return $"OK: {input.Name}";
}
```

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/11.Mvc.BindingAndValidation
```
Порт: `5011`.

### Тестові сценарії

1. **Прив'язка списку з query string:**
   ```http
   GET http://localhost:5011/bind/query?q=phone&tags=apple&tags=sale&page=2
   ```
   cURL:
   ```bash
   curl -s "http://localhost:5011/bind/query?q=phone&tags=apple&tags=sale&page=2"
   ```
   У відповіді: `tags` розпарсено у масив `["apple", "sale"]`.

2. **Прив'язка заголовка:**
   ```http
   GET http://localhost:5011/bind/header
   X-Tenant: Enterprise
   ```
   cURL:
   ```bash
   curl -s -i http://localhost:5011/bind/header -H "X-Tenant: Enterprise"
   ```
   Якщо заголовок не надіслати, `[ApiController]` автоматично поверне `400 Bad Request`.

3. **Автоматична валідація DataAnnotations (помилка 400):**
   ```http
   POST http://localhost:5011/validate
   Content-Type: application/json

   {
     "name": "A",
     "price": -10,
     "categoryId": 0
   }
   ```
   cURL:
   ```bash
   curl -s -i -X POST http://localhost:5011/validate -H "Content-Type: application/json" -d "{\"name\":\"A\",\"price\":-10,\"categoryId\":0}"
   ```
   Відповідь: `400 Bad Request` із RFC 9457 `ValidationProblemDetails`, де перераховано всі помилки для кожного поля.

4. **Бізнес-помилка (відсутня категорія):**
   ```http
   POST http://localhost:5011/validate
   Content-Type: application/json

   {
     "name": "Ноутбук Lenovo",
     "price": 999.00,
     "categoryId": 999
   }
   ```
   cURL:
   ```bash
   curl -s -i -X POST http://localhost:5011/validate -H "Content-Type: application/json" -d "{\"name\":\"Ноутбук Lenovo\",\"price\":999.00,\"categoryId\":999}"
   ```
   Повертає `400 Bad Request` із помилкою для поля `CategoryId`.

## Питання для самоперевірки та співбесіди

1. **Яку автоматичну магію виконує атрибут `[ApiController]`?**
   *Відповідь:*
   - Автоматично перевіряє `ModelState.IsValid` перед виконанням action і повертає `400 ValidationProblemDetails`, якщо валідація провалена (не потрібно писати `if (!ModelState.IsValid)`).
   - Автоматично виводить джерела прив'язки моделей (`[FromBody]` для складних типів, `[FromRoute]` для параметрів шляху, `[FromQuery]` для інших).
   - Вимагає наявності атрибутної маршрутизації (`[Route]`).
   - Перетворює помилки безпосередньо у стандартизований RFC 9457 `ProblemDetails`.
2. **Як прив'язати масив або список значень із рядка запиту (Query String)?**
   *Відповідь:* Можна передавати кілька однакових ключів: `?tags=apple&tags=sale` або використовувати квадратні дужки: `?tags[0]=apple&tags[1]=sale`. ASP.NET Core автоматично прив'яже їх до параметра типу `string[]` або `List<string>`.
3. **Чим відрізняється валідація через DataAnnotations від бізнес-валідації в дії контролера?**
   *Відповідь:* DataAnnotations перевіряють синтаксичну структуру та формати (довжина рядка, діапазон чисел, regex, наявність поля) без доступу до бази даних. Бізнес-валідація (наприклад, чи існує категорія в БД, чи активний акаунт) виконується в сервісах/контролері й у разі збою додається в `ModelState.AddModelError(...)`.

---

## Підсумки
- Атрибут `[ApiController]` суттєво спрощує код дій, беручи на себе рутинну перевірку `ModelState.IsValid`.
- Завжди повертайте помилки валідації через `ValidationProblem()`, щоб клієнти вашого API отримували передбачуваний та стандартизований контракт помилок.

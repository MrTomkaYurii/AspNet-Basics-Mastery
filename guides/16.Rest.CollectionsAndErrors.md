# 16. REST: Колекції, пагінація та помилки (16.Rest.CollectionsAndErrors)

## Призначення та огляд

Коли ресурсів стає багато, повертати весь список в одному масиві неприпустимо: це створює надмірне навантаження на базу даних, пам'ять сервера та мережу.

Цей проєкт демонструє:
1. **Дизайн колекцій у REST**: ідентифікатор ресурсу залишається незмінним (`/products`), а керування вибіркою (пагінація, фільтрація, пошук) здійснюється виключно через **Query String**;
2. **Конверт відповіді (Envelope / Paged Result)** для метаданих сторінки;
3. **Стандартизовані помилки Problem Details (RFC 9457)** із власними розширеннями (`extensions`).

---

## Пагінація: структура конверта `Page<T>`

Клієнту для відображення інтерфейсу сторінок потрібна інформація про загальну кількість елементів, номер сторінки та розмір сторінки.

```csharp
public sealed record Page<T>(
    IReadOnlyList<T> Items,
    int Page,
    int PageSize,
    int TotalCount)
{
    public int TotalPages => (int)Math.Ceiling((double)TotalCount / PageSize);
    public bool HasNextPage => Page < TotalPages;
    public bool HasPreviousPage => Page > 1;
}
```

## Розбір коду: `ProductsController`

```csharp
[ApiController]
[Route("products")]
public sealed class ProductsController(ICatalog catalog) : ControllerBase
{
    // GET /products?q=&page=1&pageSize=10
    [HttpGet]
    public ActionResult<Page<Product>> GetPage(
        [FromQuery] string? q,
        [FromQuery] int page = 1,
        [FromQuery] int pageSize = 10)
    {
        // Валідація параметрів запиту
        if (pageSize is < 1 or > 100)
        {
            ModelState.AddModelError(nameof(pageSize), "Має бути в діапазоні 1..100.");
            return ValidationProblem(ModelState);
        }

        var filtered = catalog.GetProducts()
            .Where(p => string.IsNullOrWhiteSpace(q)
                     || p.Name.Contains(q, StringComparison.OrdinalIgnoreCase))
            .ToList();

        var pageNumber = Math.Max(page, 1);
        var items = filtered
            .Skip((pageNumber - 1) * pageSize)
            .Take(pageSize)
            .ToList();

        // Також дублюємо загальну кількість у HTTP-заголовок (зручно для деяких клієнтів)
        Response.Headers["X-Total-Count"] = filtered.Count.ToString();
        return new Page<Product>(items, pageNumber, pageSize, filtered.Count);
    }

    // Кастомні поля в ProblemDetails
    [HttpGet("{id:int}")]
    public ActionResult<Product> GetById(int id)
    {
        if (catalog.FindProduct(id) is { } p)
            return p;

        return Problem(
            title: "Товар не знайдено",
            statusCode: StatusCodes.Status404NotFound,
            extensions: new Dictionary<string, object?> { ["productId"] = id });
    }
}
```

## Розширення стандарту Problem Details (RFC 9457)

Стандарт дозволяє додавати довільні додаткові властивості у словник `extensions`:
```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Товар не знайдено",
  "status": 404,
  "productId": 999
}
```
Це дозволяє фронтенду автоматично локалізувати проблему або виконати специфічну обробку без парсингу тексту повідомлення.

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/16.Rest.CollectionsAndErrors
```
Порт: `5016`.

### Тестові сценарії

1. **Пагінація за замовчуванням (сторінка 1, розмір 10):**
   ```http
   GET http://localhost:5016/products
   ```

2. **Пошук за назвою та перша сторінка:**
   ```http
   GET http://localhost:5016/products?q=pad&page=1&pageSize=2
   ```
   Повертає фільтрований список та обчислені `totalPages`, `hasNextPage`.

3. **Перевірка лімітів pageSize (валідація 400):**
   ```http
   GET http://localhost:5016/products?pageSize=500
   ```
   Повертає `400 ValidationProblemDetails`: `Має бути в діапазоні 1..100.`.

4. **Розширений ProblemDetails для 404:**
   ```http
   GET http://localhost:5016/products/999
   ```
   Містить додаткове поле `"productId": 999`.

---

## Підсумки
- Ніколи не додавайте стан сторінки в URI (наприклад `/products/page/2` — погано, `/products?page=2` — добре).
- Завжди обмежуйте максимальний розмір сторінки (`pageSize <= 100`), щоб уникнути виснаження пам'яті сервера.

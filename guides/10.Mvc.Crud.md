# 10. CRUD на MVC-контролерах (10.Mvc.Crud)

## Призначення та огляд

Цей проєкт демонструє класичну модель побудови RESTful Web API на основі **контролерів MVC** (`ControllerBase`).
У ньому реалізовано повний життєвий цикл CRUD для сутності «Товар» (`Product`):
- **C**reate (Створення) → `POST /products`
- **R**ead (Читання) → `GET /products` та `GET /products/{id}`
- **U**pdate (Повне оновлення) → `PUT /products/{id}`
- **D**elete (Видалення) → `DELETE /products/{id}`

Головна увага приділена правильним HTTP-статус-кодам, семантиці дій та поверненню заголовка `Location`.

---

## Таблиця операцій та статус-кодів

| Операція | HTTP Метод | URL | Очікуваний статус | Особливості |
|---|---|---|:---:|---|
| Список | `GET` | `/products` | **200 OK** | Порожній масив `[]` — це теж успіх 200, а не 404! |
| Отримання | `GET` | `/products/{id}` | **200 OK** або **404 Not Found** | Перевірка наявності ресурсу |
| Створення | `POST` | `/products` | **201 Created** | Обов'язковий заголовок `Location` на створений ресурс |
| Заміна | `PUT` | `/products/{id}` | **200 OK** або **404 Not Found** | Ідемпотентна операція повної заміни ресурсу |
| Видалення | `DELETE` | `/products/{id}` | **204 No Content** | Ідемпотентна: повторне видалення повертає теж 204 |

## Розбір коду: `ProductsController`

### 1. Оголошення контролера та Primary Constructor
```csharp
[ApiController]
[Route("products")]
public sealed class ProductsController(ICatalog catalog) : ControllerBase
```
- `[ApiController]` активує авто-перевірку вхідних даних, вивід джерел прив'язки та генерацію ProblemDetails.
- Primary Constructor у C# напряму впроваджує `ICatalog` у поле класу.

### 2. Створення ресурсу та `CreatedAtAction`
```csharp
[HttpPost]
public ActionResult<Product> Create(ProductInput input)
{
    if (catalog.FindCategory(input.CategoryId) is null)
        return BadRequest("Категорії з таким Id немає.");

    var created = catalog.Add(input);
    return CreatedAtAction(nameof(GetById), new { id = created.Id }, created);
}
```
Метод `CreatedAtAction`:
1. Встановлює статус `201 Created`;
2. Генерує заголовок `Location: http://localhost:5010/products/{id}`;
3. Повертає створений об'єкт `Product` у тілі відповіді.

### 3. Ідемпотентне видалення (`204 No Content`)
```csharp
[HttpDelete("{id:int}")]
public IActionResult Delete(int id)
{
    catalog.Delete(id);
    return NoContent(); // 204 без тіла
}
```
Клієнт надіслав запит з наміром "зроби так, щоб цього ресурсу не існувало". Навіть якщо ресурсу вже немає, цільовий стан досягнуто — сервер повертає 204.

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/10.Mvc.Crud
```
Порт: `5010`.

### Тестові сценарії

1. **Отримання всіх товарів:**
   ```http
   GET http://localhost:5010/products
   ```

2. **Отримання конкретного товару:**
   ```http
   GET http://localhost:5010/products/1
   ```

3. **Створення нового товару:**
   ```http
   POST http://localhost:5010/products
   Content-Type: application/json

   {
     "name": "Механічна клавіатура",
     "price": 89.99,
     "categoryId": 2
   }
   ```
   Зверніть увагу на статус `201 Created` та заголовок `Location`.

4. **Видалення товару:**
   ```http
   DELETE http://localhost:5010/products/3
   ```
   Повертає `204 No Content`.

---

## Підсумки
- MVC-контролери надають звичну об'єктно-орієнтовану структуру для організації ресурсів.
- Використання типізованого `ActionResult<T>` дає можливість повертати як конкретну сутність `T`, так і результати дій (`NotFound()`, `BadRequest()`).

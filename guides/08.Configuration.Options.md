# 08. Конфігурація та патерн Options (08.Configuration.Options)

## Призначення та огляд

Замість того, щоб читати налаштування через рядкові ключі (`config["Catalog:StoreName"]`) по всьому коду застосунку, у .NET використовується **Options Pattern** (патерн типізованих опцій).

Він забезпечує:
1. **Строгу типізацію** (налаштування стають властивостями C#-класу з автодоповненням в IDE);
2. **Валідацію на старті (`ValidateOnStart`)** — застосунок не запуститься, якщо в конфізі допущено помилку;
3. **Гнучкість життєвого циклу** через три інтерфейси: `IOptions<T>`, `IOptionsSnapshot<T>` та `IOptionsMonitor<T>`.

---

## Порівняння трьох інтерфейсів Options

| Інтерфейс | DI Час життя | Підтримка гарячого оновлення (Hot Reload)? | Де можна інжектувати? |
|---|---|:---:|---|
| **`IOptions<T>`** | **Singleton** | ❌ Ні (значення фіксується при першому зверненні) | Будь-де (контролери, сервіси, middleware, singletons) |
| **`IOptionsSnapshot<T>`** | **Scoped** | ✅ Так (перечитується заново на кожен новий HTTP-запит) | Тільки у **Scoped** або **Transient** (контролери, сервіси запиту). **Заборонено в Singleton!** |
| **`IOptionsMonitor<T>`** | **Singleton** | ✅ Так (завжди віддає найсвіжіше `CurrentValue` + подія `OnChange`) | Будь-де, зокрема в **Singleton**, фонових задачах та middleware |

## Розбір коду

### 1. Клас конфігурації з валідацією
```csharp
public sealed class CatalogOptions
{
    public const string SectionName = "Catalog";

    [Required, MinLength(3)]
    public string StoreName { get; init; } = "";

    [Range(1, 100)]
    public int PageSize { get; init; } = 20;

    public bool ExperimentalSearch { get; init; }
}
```

### 2. Реєстрація та валідація на старті
```csharp
builder.Services
    .AddOptions<CatalogOptions>()
    .Bind(builder.Configuration.GetSection(CatalogOptions.SectionName))
    .ValidateDataAnnotations()
    .ValidateOnStart(); // Падіння з інформативною помилкою НА СТАРТІ, а не посеред роботи!
```

> [!TIP]
> `ValidateOnStart()` є обов'язковою практикою для Cloud-Native систем (Fail Fast): краще, щоб контейнер не пройшов перевірку старту при деплої з битим конфігом, ніж падав через 2 дні при першому запиті до функції.

### 3. Діагностика: повне дерево джерел
```csharp
[HttpGet("/sources")]
public ContentResult Sources([FromServices] IConfiguration config)
    => Content(((IConfigurationRoot)config).GetDebugView());
```
`GetDebugView()` показує кожне значення конфігурації та те, з якого саме джерела воно було прочитано (`appsettings.json`, змінні середовища, тощо).

## Питання для самоперевірки та співбесіди

1. **У чому ключова різниця між `IOptions<T>`, `IOptionsSnapshot<T>` та `IOptionsMonitor<T>`?**
   *Відповідь:*
   - `IOptions<T>`: Singleton, обчислюється один раз під час першого звернення. Не реагує на зміни файлу конфігурації.
   - `IOptionsSnapshot<T>`: Scoped, перераховується для кожного HTTP-запиту. Підтримує гаряче оновлення файлів на диску, але **не може інжектуватися в Singleton**.
   - `IOptionsMonitor<T>`: Singleton, дозволяє читати актуальні дані через `CurrentValue` і слухати події зміни через `OnChange(...)`. Безпечний для Singleton та Hosted Services.
2. **Що робить метод `ValidateOnStart()` у підсистемі Options?**
   *Відповідь:* За замовчуванням опції валідуються "ліниво" (lazy) — коли до них вперше звертаються під час HTTP-запиту. `ValidateOnStart()` змушує ASP.NET Core виконати валідацію під час запуску застосунку (Fail-Fast принцип). Якщо файл конфігурації містить помилки, застосунок не запуститься, запобігаючи падінням у рантаймі.
3. **Чому варто уникати прямого інжектування `IConfiguration` у бізнес-сервіси?**
   *Відповідь:* Пряме використання `IConfiguration["Section:Key"]` порушує типізацію, призводить до «магічних рядків», ускладнює unit-тестування (важко мокати) та не підтримує автоматичну валідацію значень.

---

## Підсумки
- Завжди використовуйте типізовані класи опцій замість прямого читання рядків через `IConfiguration["..."]`.
- Використовуйте `IOptions<T>` за замовчуванням, якщо не потрібне гаряче оновлення.
- Використовуйте `IOptionsSnapshot<T>` для контролерів, якщо налаштування можуть змінюватися на льоту.
- Використовуйте `IOptionsMonitor<T>` для Singleton-сервісів, middleware та фонових воркерів.
- Обов'язково застосовуйте `ValidateDataAnnotations()` та `ValidateOnStart()`.

# 00. Спільна основа (00.Common)

## Призначення та огляд

Проєкт `00.Common` є спільною бібліотекою (`Class Library`), яка підключається через `<ProjectReference>` до всіх прикладів курсу. Її мета — надати єдину, зрозумілу предметну область (каталог товарів) та спільну інфраструктуру інтерактивної документації OpenAPI, щоб у кожному навчальному проєкті студенти фокусувалися на механізмах платформи **ASP.NET Core**, а не на написанні однакових моделей чи налаштуванні Swagger.

---

## Архітектура та складові

Бібліотека складається з трьох ключових блоків:

```
00.Common/
├── Domain/
│   ├── Category.cs       # Категорія товарів
│   ├── Product.cs        # Ресурс "Товар" (з версіонуванням для ETag)
│   ├── ProductInput.cs   # DTO для створення/оновлення з DataAnnotations
│   └── ICatalog.cs       # Інтерфейс репозиторію каталогу
├── InMemoryCatalog.cs    # Потокобезпечна реалізація репозиторію в пам'яті
├── CatalogServiceCollectionExtensions.cs # Extension-метод AddCatalog() для DI
└── ApiDocs.cs            # Спільне налаштування OpenAPI, Swagger UI та Scalar
```

### 1. Доменні моделі (`Domain/`)
- **`Product`**: Незмінний запис (`sealed record`), що представляє ресурс у термінах REST. Містить `Id`, `Name`, `Price`, `CategoryId` та лічильник `Version` (використовується для ETag та оптимістичного блокування).
- **`Category`**: Незмінний запис категорії з числовим `Id`, `Name` та текстовим `Slug` (для гарних URL).
- **`ProductInput`**: Вхідна модель (DTO), відокремлена від сутності `Product`. Клієнт не передає `Id` або `Version` — їх призначає сервер. Містить атрибути валідації (`[Required]`, `[StringLength]`, `[Range]`).
- **`ICatalog`**: Інтерфейс сховища, що абстрагує доступ до даних згідно з принципом Dependency Inversion (DIP).

### 2. Сховище `InMemoryCatalog`
- Реалізує `ICatalog` у пам'яті за допомогою колекцій C# та початкових даних (seed data).
- **Потокобезпека (.NET 10):** Використовує новий тип `System.Threading.Lock` (`private readonly Lock _gate = new();`), що гарантує коректну роботу при паралельних HTTP-запитах та тестах.
- Зареєстрований як **Singleton** (`AddCatalog()`).

### 3. Допоміжний клас `ApiDocs`
Надає два розширення:
- `services.AddApiDocs()` — реєструє вбудований у .NET генератор OpenAPI (`AddOpenApi()`).
- `app.MapApiDocs()` — мапить ендпоінт специфікації `/openapi/v1.json` та підключає одночасно два інтерактивні клієнти:
  - `/swagger` — класичний **Swagger UI** (`Swashbuckle.AspNetCore.SwaggerUI`);
  - `/scalar` — сучасний **Scalar API Reference** (`Scalar.AspNetCore`).

## Розбір кодового базису

### Реєстрація сервісу через метод-розширення
```csharp
public static class CatalogServiceCollectionExtensions
{
    public static IServiceCollection AddCatalog(this IServiceCollection services)
        => services.AddSingleton<ICatalog, InMemoryCatalog>();
}
```
Це ідіоматичний підхід у .NET для інкапсуляції реєстрації залежностей модуля.

### Паралельна робота Swagger UI та Scalar
```csharp
public static WebApplication MapApiDocs(this WebApplication app)
{
    app.MapOpenApi();                                                              // /openapi/v1.json
    app.UseSwaggerUI(o => o.SwaggerEndpoint("/openapi/v1.json", "API v1"));         // /swagger
    app.MapScalarApiReference(o => o.WithOpenApiRoutePattern("/openapi/v1.json"));  // /scalar

    app.OpenBrowserOnStart();
    return app;
}
```
Обидва UI є просто клієнтськими застосунками (HTML/JS), які звертаються до єдиного джерела правди — `/openapi/v1.json`. Вони працюють паралельно без конфліктів.

## Як використовувати у проєктах курсу

У будь-якому новому проєкті достатньо:
1. Додати посилання на проєкт:
   ```xml
   <ProjectReference Include="..\00.Common\Common.csproj" />
   ```
2. У фазі сервісів `Program.cs`:
   ```csharp
   builder.Services.AddCatalog();
   builder.Services.AddApiDocs();
   ```
3. У фазі конвеєра:
   ```csharp
   app.MapApiDocs();
   ```

## Питання для самоперевірки та співбесіди

1. **Чому в сучасних веб-застосунках важливо розділяти доменну модель (`Product`) та вхідну модель (`ProductInput` / DTO)?**
   *Відповідь:* Це запобігає атакам перепризначення (Over-Posting / Mass Assignment). Клієнт не повинен мати змоги передати поля, які контролює лише сервер (наприклад, внутрішній `Id`, системні аудиторські поля або `Version`).
2. **Чим `System.Threading.Lock` у C# 13 / .NET 10 кращий за старий `lock (new object())`?**
   *Відповідь:* Новий тип `Lock` надає компіляторну оптимізацію без зайвого виділення пам'яті (zero-allocation pattern) та API на основі `ref struct` (`Lock.Scope`), що робить захоплення блокування безпечнішим і продуктивнішим для JIT.
3. **Як реалізовано автоматичне відкриття браузера у викладацькому рішенні?**
   *Відповідь:* Через подію `IHostApplicationLifetime.ApplicationStarted`, яка після старту сервера зчитує призначену адресу та викликає системний процес для відкриття сторінки документації у браузері за замовчуванням.

## Підсумки та висновки
- Бібліотека `00.Common` демонструє принцип **DRY (Don't Repeat Yourself)** для спільних моделей і конфігурації.
- Застосування `System.Threading.Lock` показує сучасні можливості оптимізації багатопоточності в .NET 10.
- Централізований помічник документації гарантує, що кожен приклад можна відкрити і протестувати як у Swagger, так і в Scalar без повторного написання бойлерплейту.

# 10. CRUD на Minimal APIs (10.MinimalApi.Crud)

## Призначення та огляд

Цей приклад демонструє реалізацію повноцінного CRUD Web API за допомогою парадигми **Minimal APIs** у .NET 10.

Minimal APIs були представлені в .NET 6 та суттєво розширені в .NET 7, 8, 9 та 10. Сьогодні це рекомендований стандарт для створення високопродуктивних REST API, мікросервісів та Cloud-Native застосунків завдяки мінімальному споживанню пам'яті, миттєвому холодному старту та прямій реєстрації маршрутів без reflection-сканування контролерів.

---

## Порівняння: MVC Контролери проти Minimal APIs

| Критерій | MVC Контролери (`10.Mvc.Crud`) | Minimal APIs (`10.MinimalApi.Crud`) |
|---|---|---|
| **Місце реєстрації** | Окремі класи контролерів (`ControllerBase`) | Прямо в `Program.cs` або через методи розширення `MapGroup` |
| **Оверхед** | Створення екземплярів контролера, фільтри, сканування рефлексією | Прямий виклик функціонального делегата |
| **Типізація відповідей** | `ActionResult<T>` (нетипізовані статус-коди в сигнатурі) | `TypedResults` (`Results<Ok<T>, NotFound>`) зі строгою перевіркою компілятора |
| **OpenAPI / Swagger** | Потребує ручних атрибутів `[ProducesResponseType]` | **Автоматично генерує схеми** та коди на основі типів `TypedResults` |
| **Групування шляхів** | `[Route("products")]` над класом | `app.MapGroup("/products")` |

## Розбір коду

### 1. Організація маршрутів через `MapGroup`
```csharp
var products = app.MapGroup("/products")
    .WithTags("Products");
```
`MapGroup` задає спільний префікс шляху та додає метадані для документації OpenAPI (тег `"Products"`).

### 2. Отримання товару з використанням `TypedResults`
```csharp
products.MapGet("/{id:int}", Results<Ok<Product>, NotFound> (int id, ICatalog catalog) =>
{
    return catalog.FindProduct(id) is { } p
        ? TypedResults.Ok(p)
        : TypedResults.NotFound();
})
.WithName("GetProductById")
.WithSummary("Отримати товар за ідентифікатором");
```
- Сигнатура повертає `Results<Ok<Product>, NotFound>`.
- Якщо розробник спробує повернути статус, не зазначений у цій сигнатурі, код не скомпілюється!
- OpenAPI автоматично фіксує у документі коди `200` (зі схемою `Product`) та `404`.

### 3. Створення ресурсу з `TypedResults.CreatedAtRoute`
```csharp
products.MapPost("/", Results<CreatedAtRoute<Product>, BadRequest<string>> (ProductInput input, ICatalog catalog) =>
{
    if (catalog.FindCategory(input.CategoryId) is null)
        return TypedResults.BadRequest("Категорії з таким Id немає.");

    var created = catalog.Add(input);
    return TypedResults.CreatedAtRoute(created, "GetProductById", new { id = created.Id });
})
.WithName("CreateProduct");
```
Метод формує заголовок `Location`, спираючись на іменований маршрут `"GetProductById"`.

### 4. Видалення з `NoContent`
```csharp
products.MapDelete("/{id:int}", NoContent (int id, ICatalog catalog) =>
{
    catalog.Delete(id);
    return TypedResults.NoContent();
})
.WithName("DeleteProduct");
```

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/10.MinimalApi.Crud
```
Порт: `5110`.

### Тестові сценарії

1. **Отримати всі товари:**
   ```http
   GET http://localhost:5110/products
   Accept: application/json
   ```
   cURL:
   ```bash
   curl -s http://localhost:5110/products
   ```

2. **Отримати товар за Id:**
   ```http
   GET http://localhost:5110/products/1
   Accept: application/json
   ```
   cURL:
   ```bash
   curl -s http://localhost:5110/products/1
   ```

3. **Створити товар:**
   ```http
   POST http://localhost:5110/products
   Content-Type: application/json

   {
     "name": "Механічна клавіатура Keychron",
     "price": 119.50,
     "categoryId": 2
   }
   ```
   cURL:
   ```bash
   curl -s -X POST http://localhost:5110/products -H "Content-Type: application/json" -d "{\"name\":\"Механічна клавіатура Keychron\",\"price\":119.50,\"categoryId\":2}"
   ```
   Перевірте статус `201 Created` та посилання в заголовку `Location`.

4. **Видалити товар:**
   ```http
   DELETE http://localhost:5110/products/3
   ```
   cURL:
   ```bash
   curl -s -i -X DELETE http://localhost:5110/products/3
   ```
   Повертає `204 No Content`.

5. **Інтерактивна документація:**
   Відкрийте `http://localhost:5110/scalar` і переконайтеся, що всі коди помилок та моделі автоматично присутні в інтерфейсі без жодного атрибута `[ProducesResponseType]`.

## Питання для самоперевірки та співбесіди

1. **У чому головна архітектурна відмінність між `Results` та `TypedResults`?**
   *Відповідь:* `Results.Ok(...)` повертає нетипізований інтерфейс `IResult`. Натомість `TypedResults.Ok<T>(...)` повертає конкретну типізовану реалізацію `Ok<T>`. Це дозволяє компілятору перевіряти типи, вимагати точну сигнатуру методів у `Results<Ok<T>, NotFound>` і автоматично генерувати повну схему OpenAPI без ручних атрибутів.
2. **Як `MapGroup` допомагає структурувати великі API?**
   *Відповідь:* `MapGroup` дозволяє винести спільний префікс шляху (наприклад, `/api/v1/orders`), налаштувати групову авторизацію (`.RequireAuthorization()`), валідацію, спільні фільтри або теги для OpenAPI в одному місці, а маршрути розбити на окремі класи-розширення.
3. **Чи можна тестувати маршрути Minimal API unit-тестами без запуску HTTP-сервера?**
   *Відповідь:* Так! Оскільки делегати хендлерів повертають `TypedResults`, їх можна тестувати як звичайні C#-методи, перевіряючи конкретний тип результату (наприклад, `Assert.IsType<Ok<Product>>(result.Result)`).

## Підсумки
- Minimal APIs у .NET 10 надають найсучасніший, швидкий та типобезпечний синтаксис для створення веб-сервісів.
- Використання `TypedResults` робить API детермінованим, дружнім до unit-тестів та ідеально задокументованим у OpenAPI.

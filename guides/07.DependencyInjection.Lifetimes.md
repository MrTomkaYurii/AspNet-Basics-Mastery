# 07. Час життя сервісів у Dependency Injection (07.DependencyInjection.Lifetimes)

## Призначення та огляд

Вбудований контейнер інверсії керування (IoC / DI Container) у .NET є фундаментальним будівельним блоком усього фреймворку. Він керує створенням екземплярів об'єктів та їхнім життєвим циклом.

Цей проєкт на практиці демонструє три стандартні часи життя сервісів:
- **`Transient`** (Тимчасовий)
- **`Scoped`** (В межах області запиту)
- **`Singleton`** (Один на весь застосунок)

А також показує, як коректно створювати області вручну через `IServiceScopeFactory`.

---

## Три часи життя: порівняльна таблиця

| Час життя | Метод реєстрації | Коли створюється новий екземпляр? | Для чого підходить? |
|---|---|---|---|
| **Transient** | `AddTransient<TInterface, TImpl>()` | При **кожному** зверненні до контейнера (навіть двічі в межах одного запиту) | Легковажні сервіси без стану, утиліти, валідатори |
| **Scoped** | `AddScoped<TInterface, TImpl>()` | **Один раз на HTTP-запит** (на DI-область). Екземпляр спільний для middleware і контролера | Контексти бази даних (`DbContext`), репозиторії, стан поточного користувача |
| **Singleton** | `AddSingleton<TInterface, TImpl>()` | **Один раз** при першому виклику. Живе до зупинки процесу | Кеші в пам'яті, клієнти з пулом з'єднань (`HttpClientFactory`, черги), конфігурація |

## Розбір коду

### 1. Модель операції з унікальним ID
```csharp
public interface IOperation { Guid Id { get; } }
public interface ITransientOperation : IOperation;
public interface IScopedOperation : IOperation;
public interface ISingletonOperation : IOperation;

public sealed class Operation : ITransientOperation, IScopedOperation, ISingletonOperation
{
    public Guid Id { get; } = Guid.NewGuid();
}
```
Кожен новий створений екземпляр отримує новий `Guid`. Порівнюючи ці ідентифікатори у відповіді API, можна точно побачити поведінку контейнера.

### 2. Взаємодія Middleware та Контролера
У `Program.cs` middleware запам'ятовує `Id` сервісу `IScopedOperation`:
```csharp
app.Use(async (context, next) =>
{
    var scoped = context.RequestServices.GetRequiredService<IScopedOperation>();
    context.Items["scopedFromMiddleware"] = scoped.Id;
    await next(context);
});
```

У `LifetimesController.cs`:
```csharp
[HttpGet("/ids")]
public object GetIds(
    [FromServices] ITransientOperation transientA,
    [FromServices] ITransientOperation transientB)
    => new
    {
        transientA = transientA.Id,                        // ← різні між собою!
        transientB = transientB.Id,
        scoped = scoped.Id,                                // ← дорівнює scopedFromMiddleware!
        scopedFromMiddleware = HttpContext.Items["scopedFromMiddleware"],
        singleton = singleton.Id,                          // ← однаковий для всіх запитів
    };
```

### 3. Ручне створення областей через `IServiceScopeFactory`
```csharp
[HttpGet("/scopes")]
public object GetScopes([FromServices] IServiceScopeFactory scopeFactory)
{
    using var a = scopeFactory.CreateScope();
    using var b = scopeFactory.CreateScope();
    return new
    {
        scopeA = a.ServiceProvider.GetRequiredService<IScopedOperation>().Id,
        scopeB = b.ServiceProvider.GetRequiredService<IScopedOperation>().Id, // різні області → різні Id
    };
}
```

## Пастка: Captive Dependency (Захоплена залежність)

> [!CAUTION]
> **Ніколи не впроваджуйте `Scoped`-сервіс у `Singleton`-сервіс!**
> Оскільки `Singleton` створюється один раз, він "захопить" (полонить) посилання на перший створений екземпляр `Scoped`-сервісу. У результаті:
> - `Scoped`-об'єкт ніколи не знищиться збирачем сміття (витік пам'яті).
> - Усі паралельні запити користуватимуться одним екземпляром, що спричинить стан перегонів (race condition), наприклад у `DbContext`.

У режимі **Development** ASP.NET Core автоматично виконує валідацію областей (`validateScopes: true`) і кине виняток на старті, якщо виявить таку залежність.

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/07.DependencyInjection.Lifetimes
```
Порт: `5007`.

### Тестові сценарії

1. **Порівняння ID у межах одного запиту:**
   ```http
   GET http://localhost:5007/ids
   ```
   Швидкий виклик через cURL:
   ```bash
   curl -s http://localhost:5007/ids
   ```
   Зверніть увагу:
   - `transientA` != `transientB` (два різні екземпляри);
   - `scoped` == `scopedFromMiddleware` (той самий екземпляр у межах одного HTTP-запиту);
   - Повторіть запит: `scoped` зміниться на новий, а `singleton` залишиться тим самим!

2. **Ізольовані ручні області:**
   ```http
   GET http://localhost:5007/scopes
   ```
   Швидкий виклик через cURL:
   ```bash
   curl -s http://localhost:5007/scopes
   ```
   Показує, як кожна створена область (`CreateScope()`) породжує власний окремий екземпляр `Scoped`-сервісу.

## Питання для самоперевірки та співбесіди

1. **Що таке Captive Dependency і чим вона загрожує?**
   *Відповідь:* Це ситуація, коли сервіс із довшим життєвим циклом (наприклад, `Singleton`) захоплює посилання на сервіс із коротшим циклом (`Scoped` або `Transient`). Це призводить до витоку пам'яті (об'єкт ніколи не збирається GC) та стану перегонів (race condition), якщо сервіс не є потокобезпечним (як `DbContext`).
2. **Чому `DbContext` у Entity Framework Core реєструється як `Scoped`?**
   *Відповідь:* `DbContext` відстежує зміни сутностей (change tracker) і зберігає з'єднання. Робити його `Singleton` не можна, бо він не є потокобезпечним, а `Transient` створив би різні контексти у різних репозиторіях одного запиту, що зламало б транзакційність (Unit of Work).
3. **Як отримати `Scoped`-сервіс усередині фонової задачі або `Singleton`?**
   *Відповідь:* Заінжектити `IServiceScopeFactory`, викликати `using var scope = scopeFactory.CreateScope();` і витягнути сервіс через `scope.ServiceProvider.GetRequiredService<T>()`.
4. **Що відбувається з екземплярами `IDisposable` при використанні DI?**
   *Відповідь:* Контейнер бере на себе володіння об'єктом. `Scoped`-об'єкти диспозяться автоматично в кінці HTTP-запиту, `Transient` — при знищенні області, в якій були створені, а `Singleton` — при зупинці застосунку.

---

## Підсумки
- Чітке розуміння життєвих циклів запобігає складним багам багатопоточності та витокам пам'яті.
- `Scoped` — основний вибір для бізнес-логіки та роботи з БД під час обробки веб-запитів.
- Для фонових задач використовуйте `IServiceScopeFactory` для створення контрольованих областей.

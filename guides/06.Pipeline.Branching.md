# 06. Розгалуження конвеєра: Map, MapWhen, UseWhen (06.Pipeline.Branching)

## Призначення та огляд

За замовчуванням конвеєр ASP.NET Core є лінійним: кожен запит проходить крізь усі зареєстровані middleware. Проте в реальних застосунках часто потрібно:
- Виділити ізольовану гілку для панелі адміністрування чи внутрішніх API;
- Застосувати middleware лише за певної умови (наприклад, перевірка заголовка чи префіксу шляху);
- Обробити специфічні запити від застарілих клієнтів за окремим алгоритмом.

Для цього ASP.NET Core надає три методи розгалуження: `app.Map`, `app.MapWhen` та `app.UseWhen`.

---

## Порівняння методів розгалуження

| Метод | Умова розгалуження | Поведінка гілки | Чи повертається в основний конвеєр? | Зміна `Path` / `PathBase` |
|---|---|---|:---:|---|
| **`app.Map`** | Префікс шляху URL (наприклад `"/admin"`) | **Термінальна** (завершує конвеєр) | ❌ **Ні** | Префікс обрізається: `Path` стає `"/"`, а `PathBase` — `"/admin"` |
| **`app.MapWhen`** | Довільний предикат `HttpContext -> bool` | **Термінальна** (завершує конвеєр) | ❌ **Ні** | `Path` не змінюється |
| **`app.UseWhen`** | Довільний предикат `HttpContext -> bool` | **Умовна вставка** | ✅ **Так** (якщо гілка не зробила short-circuit) | `Path` не змінюється |

## Розбір коду

### 1. `app.Map` — під-програма за префіксом
```csharp
app.Map("/admin", admin =>
    admin.Run(async ctx =>
        await ctx.Response.WriteAsync($"Адмінка. Path='{ctx.Request.Path}', PathBase='{ctx.Request.PathBase}'")));
```
- Якщо запит прийшов на `/admin/users`, то всередині гілки `Path` буде `/users`, а `PathBase` — `/admin`.
- Якщо вкладена конфігурація `admin` не обробила запит, клієнт отримає 404. Запит **не повертається** в основний конвеєр.

### 2. `app.MapWhen` — гілка за довільною умовою
```csharp
app.MapWhen(
    ctx => ctx.Request.Headers.ContainsKey("X-Legacy-Client"),
    legacy => legacy.Run(ctx => ctx.Response.WriteAsync("Гілка для застарілих клієнтів.")));
```
- Якщо заголовок присутній — запит обробляється виключно в цій гілці й завершується тут.

### 3. `app.UseWhen` — умовна вставка з поверненням
```csharp
app.UseWhen(
    ctx => ctx.Request.Path.StartsWithSegments("/api"),
    api => api.Use(async (ctx, next) =>
    {
        if (ctx.Request.Headers["X-Api-Key"] != "secret")
        {
            ctx.Response.StatusCode = StatusCodes.Status401Unauthorized;
            await ctx.Response.WriteAsync("Потрібен X-Api-Key для /api/*");
            return; // Коротке замикання за відсутності ключа
        }
        ctx.Response.Headers["X-Api-Auth"] = "ok";
        await next(ctx); // Продовжуємо гілку
    }));
```
- Працює лише для шляхів, що починаються з `/api`.
- Якщо ключ валідний, `next(ctx)` передає керування далі, і після завершення гілки запит **повертається в основний конвеєр**, потрапляючи в кінцеві ендпоінти (`/api/ping`, `/api/whoami`).

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/06.Pipeline.Branching
```
Порт: `5006`.

### Тестові сценарії

1. **Термінальна гілка `app.Map`:**
   ```http
   GET http://localhost:5006/admin
   ```
   cURL:
   ```bash
   curl -s http://localhost:5006/admin
   ```
   Відповідь: `Адмінка. Path='', PathBase='/admin'`.

2. **Термінальна гілка `app.MapWhen` (за заголовком):**
   ```http
   GET http://localhost:5006/
   X-Legacy-Client: true
   ```
   cURL:
   ```bash
   curl -s http://localhost:5006/ -H "X-Legacy-Client: true"
   ```
   Відповідь: `Гілка для застарілих клієнтів.`.

3. **Умовна вставка `app.UseWhen` без ключа:**
   ```http
   GET http://localhost:5006/api/ping
   ```
   cURL:
   ```bash
   curl -s -i http://localhost:5006/api/ping
   ```
   Відповідь: `401 Unauthorized` (`Потрібен X-Api-Key для /api/*`).

4. **Умовна вставка `app.UseWhen` з правильним ключем:**
   ```http
   GET http://localhost:5006/api/ping
   X-Api-Key: secret
   ```
   cURL:
   ```bash
   curl -s http://localhost:5006/api/ping -H "X-Api-Key: secret"
   ```
   Відповідь: `200 OK` (`pong`). Запит успішно повернувся з `UseWhen` і дійшов до `MapGet("/api/ping")`.

## Питання для самоперевірки та співбесіди

1. **У чому головна відмінність між `MapWhen` та `UseWhen`?**
   *Відповідь:* `MapWhen` створює **термінальну** ізольовану гілку. Після завершення обробки в цій гілці керування ніколи не повертається в основний пайплайн. Натомість `UseWhen` вбудовує проміжні middleware тимчасово: якщо жоден із них не перервав запит, керування повертається в основний ланцюг і продовжує йти далі.
2. **Що відбувається з `context.Request.Path` та `PathBase` усередині `app.Map("/admin", ...)`?**
   *Відповідь:* ASP.NET Core автоматично відрізає префікс `/admin` від `Path` і додає його до `PathBase`. Тому всередині гілки `Path` для кореневого запиту стає порожнім або `/`.
3. **Коли краще обрати `UseWhen` замість Endpoint Routing metadata?**
   *Відповідь:* `UseWhen` зручний для умовної обробки запитів на ранніх стадіях конвеєра до прийняття рішень маршрутизатором (наприклад, для перевірки заголовків зворотної сумісності або спеціального логування діагностичних запитів).

---

## Підсумки
- Використовуйте `app.Map`, коли створюєте повністю окрему під-систему (наприклад, незалежний пайплайн для SignalR або старого API).
- Використовуйте `app.UseWhen`, коли вам потрібно застосувати певний middleware (логування, специфічну автентифікацію, перевірку лімітів) тільки до частини маршрутів без втрати доступу до основних ендпоінтів.

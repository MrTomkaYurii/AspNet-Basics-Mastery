# 15. REST: Представлення та оптимістичне блокування (15.Rest.Representations)

## Призначення та огляд

У REST клієнт взаємодіє не з фізичним об'єктом у базі даних, а з його **представленням (Representation)**. Цей приклад розкриває три фундаментальні аспекти професійного REST API:
1. **Content Negotiation (Узгодження вмісту)** — передача даних у JSON або XML залежно від заголовка `Accept`;
2. **Валідація кешу через ETag (304 Not Modified)**;
3. **Оптимістичне блокування (Optimistic Concurrency Control)** через заголовки `If-Match` та `412 Precondition Failed` для запобігання втраті оновлень (Lost Update Problem);
4. **Часткове оновлення (PATCH)** з використанням стандарту **JSON Patch (RFC 6902)** на базі сучасного `System.Text.Json` у .NET 10 (без застарілого Newtonsoft.Json).

---

## Проблема втрати оновлень (Lost Update Problem)

Уявіть ситуацію:
1. Користувач А завантажив товар за 100 грн.
2. Користувач Б завантажив той самий товар за 100 грн.
3. Користувач А змінює ціну на 120 грн і зберігає (`PUT`).
4. Користувач Б змінює назву і зберігає (`PUT`).
**Результат без блокування:** Запит користувача Б перезапише ціну користувача А назад на 100 грн! Оновлення користувача А втрачено мовчки.

### Рішення: ETag та If-Match
- Сервер повертає у відповіді хеш або версію ресурсу в заголовку `ETag: W/"1-1"`.
- Клієнт при оновленні зобов'язаний надіслати заголовок `If-Match: W/"1-1"`.
- Якщо інший клієнт уже змінив ресурс, версія на сервері стане `W/"1-2"`.
- Сервер виявляє невідповідність і миттєво відхиляє запит зі статусом **`412 Precondition Failed`**, захищаючи дані від затирання!

## Розбір коду: `ProductsController`

### 1. Перевірка кешу на GET: `ETag` + `If-None-Match`
```csharp
[HttpGet("{id:int}")]
public ActionResult<ProductRepresentation> Get(int id)
{
    if (catalog.FindProduct(id) is not { } product)
        return NotFound();

    var etag = ETag(product);
    // Якщо у клієнта все ще свіжа версія:
    if (Request.Headers.IfNoneMatch == etag)
        return StatusCode(StatusCodes.Status304NotModified); // 304 без передачі тіла!

    Response.Headers.ETag = etag;
    Response.Headers.CacheControl = "private, max-age=30";
    return ProductRepresentation.From(product);
}
```

### 2. Оптимістичне блокування на PUT: `If-Match`
```csharp
[HttpPut("{id:int}")]
public ActionResult<ProductRepresentation> Put(int id, ProductRepresentation body)
{
    if (catalog.FindProduct(id) is not { } current)
        return NotFound();

    if (Request.Headers.IfMatch.Count == 0)
        return Problem("Потрібен заголовок If-Match.", statusCode: StatusCodes.Status428PreconditionRequired);

    if (Request.Headers.IfMatch != ETag(current))
        return Problem("Ресурс змінено іншим клієнтом.", statusCode: StatusCodes.Status412PreconditionFailed);

    var updated = catalog.Replace(id, body.ToInput())!;
    Response.Headers.ETag = ETag(updated);
    return ProductRepresentation.From(updated);
}
```

### 3. JSON Patch (RFC 6902) на System.Text.Json
```csharp
[HttpPatch("{id:int}")]
[Consumes("application/json-patch+json")]
public ActionResult<ProductRepresentation> Patch(int id, JsonPatchDocument<ProductRepresentation> patch)
{
    if (catalog.FindProduct(id) is not { } current)
        return NotFound();

    var draft = ProductRepresentation.From(current);
    patch.ApplyTo(draft); // Застосовує перелік дій (replace, add, remove)
    var updated = catalog.Replace(id, draft.ToInput())!;
    return ProductRepresentation.From(updated);
}
```

## Як запустити і перевірити

### Запуск проєкту
```bash
dotnet run --project src/15.Rest.Representations
```
Порт: `5015`.

### Тестові сценарії

1. **Читання з отриманням ETag:**
   ```http
   GET http://localhost:5015/products/1
   ```
   У заголовках повертається: `ETag: W/"1-1"`.

2. **Умовний GET (економія трафіку):**
   ```http
   GET http://localhost:5015/products/1
   If-None-Match: W/"1-1"
   ```
   Сервер повертає **`304 Not Modified`** без тіла запиту.

3. **Спроба оновити без заголовка `If-Match`:**
   ```http
   PUT http://localhost:5015/products/1
   Content-Type: application/json

   { "name": "Нова назва", "price": 99, "categoryId": 1 }
   ```
   Сервер вимагає заголовок: **`428 Precondition Required`**.

4. **Оновлення з застарілим `If-Match`:**
   ```http
   PUT http://localhost:5015/products/1
   If-Match: W/"1-999"
   Content-Type: application/json

   { "name": "Нова назва", "price": 99, "categoryId": 1 }
   ```
   Повертає **`412 Precondition Failed`**!

5. **Часткове оновлення JSON Patch:**
   ```http
   PATCH http://localhost:5015/products/1
   Content-Type: application/json-patch+json

   [
     { "op": "replace", "path": "/price", "value": 1500.00 }
   ]
   ```
   Змінює виключно поле `price`.

---

## Підсумки
- `ETag` + `If-Match` — найнадійніший механізм конкурентного редагування в розподілених системах без блокування рядків у базі даних.
- `System.Text.Json` у .NET 10 надає високопродуктивну підтримку RFC 6902 JSON Patch без додаткових сторонніх залежностей.
